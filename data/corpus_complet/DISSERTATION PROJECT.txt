tive and incremental projects of diﬀerent types. The whole concept is centred on breaking
large complex projects into smaller stages, reviewing and adapting along the way.

The activity diagram begins with setting the essentials part of the 3D context (the scene

handler must be called to handle how the scene will be updated.
Frame Handler
The ﬁrst step of the frame handler is to reset frame values. These values help Three.js to
track scene changes. Then, the frame handler tests if the model is still idle and has not
been animated before. If the test returns true, the ﬁrst animation will be triggered and
it raises a ﬂag that indicates the beginning of an animation series. Otherwise, this test
will be skipped.
After this step, a second test will be in the queue. This test will check if there is an
active animation. If it returns true, it will do nothing. Otherwise it will check if there’s
still at least one animation in the queue and trigger it.

REST-based
ElasticSearch is based on REST architecture and provides API endpoints to not only

REST endpoints also enable users to
make changes to clusters and indices settings dynamically, rather than manually pushing

and so on) in ElasticSearch is accessible via a simple URI.[32]
Powerful Query DSL
Query DSL (domain-speciﬁc language) is a JSON interface provided by Elasticsearch to

in advance in some cases. When you send your ﬁrst document to Elasticsearch, it tries it
best to parse every ﬁeld in the document and creates a schema itself. Next time, if you
send another document. So, Elasticsearch is not completely schemaless but its dynamic
behavior of creating a schema is very useful.

5.4.7
Getting familiar with ElasticSearch common terms
The following are the most common terms that are very important to know when starting
with the Elasticsearch:
• Node: A single instance of Elasticsearch running on a machine.
• Cluster: A cluster is the single name under which one or more nodes/instances of
Elasticsearch are connected to each other.[35]
• Document: A document is a JSON object that contains the actual data in key
value pairs.
• Index: A logical name-space under which Elasticsearch stores data, and may be
built with more than one Lucene[26] index using shards and replicas.[32]
• Doc types: A doc type in Elasticsearch represents a class of similar documents.[27]
A type consists of a name, such as a user or a blog post, and a mapping, including
data types and the Lucene conﬁguration for each ﬁeld. (An index can contain more
than one type.)
• Shard: Shards are containers that can be stored on a single node or multiple nodes
and are composed of Lucene segments. An index is divided into one or more shards
to make the data distributable.
• Node: A shard can be either primary or secondary. A primary shard is the one
where all the operations that change the index are directed.[32] A secondary shard
is the one that contains duplicate data of the primary shard and helps in quickly
searching the data as well as for high availability, in a case where the machine
that holds the primary shard goes down.[32] then the secondary shard becomes the
primary automatically.[32]
• Replica: A duplicate copy of the data living in a shard for high availability.
