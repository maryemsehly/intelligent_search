General Introduction
In today’s digital age, the Internet has become an indispensable medium for communi-
cation, commerce, education, and personal expression. Websites serve as the primary
gateways for individuals and organizations to share information, provide services, and
engage with their audiences. However, despite the widespread need for a web presence,
building a compelling and functional website remains a technically challenging process
for many. Traditional development involves multiple complex layers-from frontend and
backend coding to design, responsiveness, and deploymentârequiring expertise that
not all users possess. Consequently, there is a growing demand for tools that simplify
this process and make website creation accessible to a broader audience.
In this context, Artificial Intelligence (AI) has emerged as a transformative force, particu-
larly in web development. Recent advances in generative AI, especially Large Language
Models (LLMs), have enabled powerful new tools capable of understanding user intent
expressed in natural language and generating corresponding content, code, and even
complete website structures. This project leverages these advancements to propose an
innovative AI-powered website generator. Our solution aims to significantly reduce
the complexity of web development by allowing users to describe their desired web-
site features in plain English and receive functional, high-quality code automatically,
thereby democratizing website creation in line with the broader movement towards
no-code and low-code platforms.
This report details the design, implementation, and evaluation of this AI-powered
website generator, following the structured phases of the Generative AI Project Life
Cycle. The document is organized into five chapters:
• Chapter 1: General Context and Methodology . This chapter provides the overall
background and methodological foundation for the project. It outlines the ratio-
nale for developing the AI website generator, defines the project objectives, aimed
at streamlining web creation, discusses the limitations of existing solutions, and
introduces the GenAI lifecycle methodology guiding the project, along with the
initial project plan.

text. This has led researchers such as Andrew Ng to develop a new project life cycle
represented in Figure 1.5 The GenAI project life cycle encompasses multiple pivotal

stages, each of which is essential for the effective implementation and integration of
GenAI within an organization. These stages are designed to ensure alignment with
business goals, selection of the appropriate models, and seamless integration into
applications. The project is divided into four phases [5], that can be described as
follows:
1. Scope
To define the use case, it is necessary to first identify a specific problem or oppor-
tunity. Then, the desired outcome must be determined. Finally, it is essential to
outline how GenAI can achieve this goal. The scope phase includes the following
steps:
• Problem Identification: It is imperative to articulate the problem one seeks to
solve with GenAI, such as the reduction of time required for the production
of marketing content.
• Desired Outcome: It is imperative to establish quantifiable success criteria,
such as a 50% reduction in content creation time.
• Feasibility Assessment: Take into account technical, moral, and financial
limitations to determine if GenAI is a workable solution for the identified
issue.
•
Implementation Outline: Give a clear overview of how GenAI can be
incorporated into existing procedures to solve the issue.
2. Select
The user is presented with the option of either selecting an existing model or
of pretraining a new one. Each generative model is engineered with distinct
capabilities and optimized for specific applications. For instance, models such
as ChatGPT demonstrate proficiency in text generation tasks, while DALL-E is
distinguished by its expertise in image generation. The selection of an appropriate
model for a given project is a critical decision. This decision is contingent upon a
comprehensive understanding of the unique strengths and potential limitations
inherent to each model. It is imperative to employ this discernment to ascertain
that the selected model is congruent with the objectives of the project and will

The transformer architecture serves as the foundation for LLM. It was first presented by

area of natural language processing. In contrast to RNNs and LSTM networks More

Figure 3.3: Architecture of Transformers [17].
The transformer architecture is composed of two primary components ,the encoder and
also the decoder is a factor to be considered.

• Encoder: The encoder is composed of a stack of N=6 Identical Layers [17] . Each
layer comprises the following sub-components:
– Multi-Head Self-Attention Mechanism:The model may concurrently focus on
vital segments of the input sequence thanks to the Multi-Head Self-Attention
Mechanism. Regardless of how far apart words are from one another, it
calculates the attention ratings for each word in the input sequence in respect
to every other word, capturing relationships. By carrying out many attention
operations concurrently and concatenating the results, the model’s multiple
attention heads (thus the term "multi-head") enable it to capture a variety of
linguistic properties.
– Feed-Forward Neural Network: Every layer has a feedforward network that is
completely linked and applied to every location in an identical and indepen-
dent manner. ReLU activation connects the two linear transformations that
make up this network. This facilitates the model’s ability to identify intricate,
non-linear correlations in the data.
– Layer Normalization and Residual Connections: By addressing the vanishing
gradient problem, each sub-layer aids in deep network training. Each sub-
layer’s input is normalized after being added to its output. By guaranteeing
that the inputs to the activation functions have a mean of zero and a variance
of one, layer normalization speeds up and stabilizes the training process.
– Positional Encodings for Sequence Information:In order to supply the model
with information on the location of each word in the sequence, positional
encodings are appended to the input embeddings because the transformer
lacks a sequential processing capability. At the bottom of the encoder stack,
these encodings are appended to the input embeddings.
• Decoder: The decoder is also made up of a stack of N=6 identical layers [17] .
Each layer comprises the following sub-components:
– Masked Multi-Head Self-Attention in the Decoder: A mask that stops the decoder
from responding to successive places is part of the Masked Multi-Head
Self-Attention Mechanism, which functions similarly to the encoder.

– Multi-Head Attention Mechanism (Encoder-Decoder Attention): This layer uses
the encoder’s output to accomplish multi-head attention. It enables the
decoder to generate each word of the output sequence by concentrating on
pertinent portions of the input sequence.
–
Feed-Forward Neural Network: Each layer has a completely linked feed-
forward network that is applied to every point independently and identically,
much like the encoder.
– Residual Connections and Layer Normalization: To stabilize and speed up train-
ing, residual connections and layer normalization are used, much as the
encoder described in section 3.3.2 [18].
– Positional Encoding: To give positional information, positional encodings are
appended to the input embeddings in a manner similar to that of the encoder.
The Attention Mechanism shown in Figure 3.4. is another crucial part of the trans-

5.3.2.3 Align with Human Feedback
Reinforcement Learning from Human Feedback (RLHF) is a machine learning technique
that uses human feedback to enhance the efficiency of model training. Conventional
Reinforcement Learning (RL) techniques are designed to instruct models to make
decisions that optimize rewards, thereby enhancing the precision of their outcomes.
RLHF incorporates human feedback into the reward function, thereby facilitating the
model’s execution of tasks that are more congruent with human objectives, inclinations,
and requirements [21] .
This approach is widely utilized in Generative AI applications, including LLMs. How-
ever, RLHF is not ideal for my specific use case for numerous reasons. Primarily, it
typically requires a well-defined reward function to evaluate the model’s outputs based
on human feedback. In the context of script conversion, defining a precise and objective
reward function that accurately captures the correctness and efficiency of the converted
scripts can be highly complex. Furthermore, the process entails iterative interactions
and feedback from human evaluators, which can be both resource-intensive and time-
consuming. The process of script conversion necessitates the attainment of immediate
and deterministic outcomes, wherein consistent accuracy and correctness are of the
utmost importance. This approach stands in contrast to the iterative trial-and-error
method employed by RLHF. As illustrated in Figure 4.4 , the RLHF process incorporates

70B and is integrated with a React front end and a FastAPI back end. This enables non-

in-context learning to direct the LLM in creating structured, multi-page websites. Eval-

applications in which human intent and AI will work together flawlessy to develop the

Abstract
This thesis details the design, implementation, and evaluation of an innovative AI-
powered website generator. Addressing the technical complexity of traditional web
development, this project aims to democratize website creation using Large Language
Models (LLMs). The proposed solution enables users to describe desired website
features in natural language and automatically receive high-quality, functional code.
The project follows the structured Generative AI (GenAI) project lifecycle, encompass-
ing context definition, methodology, scope delimitation, rigorous AI model selection
(specifically Llama 3 70B 8192), and model adaptation using techniques like prompt
engineering and in-context learning. Finally, it covers system integration into a func-
tional web application and cloud deployment. Evaluation focuses on both the generated
code quality and the adaptation model’s performance. This work contributes to no-
code/low-code platforms by offering a powerful tool to simplify and accelerate web
development.
