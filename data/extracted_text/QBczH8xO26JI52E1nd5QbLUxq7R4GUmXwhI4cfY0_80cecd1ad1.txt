General Introduction
In the subject of molecular biology, recently, microRNAs (miRNA) have risen to be one of
the most studied types of non-coding RNA molecules as a result of their role in regulating
gene expression [1]. For researchers who are working on identifying new therapeutic targets,
microRNAs are their key focus due to their involvement in serious diseases such as cancer,
diabetes, and leishmaniasis [2]. However, the data needed to operate this type of research is
spread across dierent scientic publications and databases, with no method to centralize them
or cross-reference them eciently and stay up to date.
MIR-ACLE Biotech, a deeptech startup in healthtech specialized in miRNA research recognized
this gap and aimed to address it. The startup set an objective to develop a solution that is an
intelligent platform that centralizes heterogeneous biological data and oers researchers ways
to accelerate their work, from AI-powered tools to run predictive analysis to data exploration
and interactive visualization.
It's at this exact point that our end-of-studies project takes place: designing and building a
web application that integrates multiple data sources, AI models for miRNA classication and
interaction prediction, interactive network visualization, and an NLP pipeline for automatic
knowledge extraction from scientic publications.
This report contains the various steps of our project, from analyzing the context and objectives
to the technical implementation.
It starts with a presentation of the general context, the
tools, and the technologies used.
Then it goes through the features developed across the
continuous iterations, detailing the related diagrams and illustrative screenshots. Finally, a
general conclusion providing a summary of the work accomplished and indicating directions for
future development.

Several methodologies have been developed over the years to address dierent project needs

 Waterfall: A linear and sequential model in which each phase must be fully completed
before the next begins. It is well-suited for projects with stable, well-dened requirements
but oers little exibility when changes arise mid-project [11].
 V-Model (Verication and Validation): An extension of Waterfall that pairs each de-

 Agile: An iterative and incremental approach that prioritizes collaboration, adaptability, and
continuous delivery of working software. It is examined in detail in the following section [14].

Justication of technology choices
a) Front-end: React.js
React.js [21] was selected for its component-based architecture enabling reusable, independently
managed UI elements. TypeScript added static type safety, while libraries such as Recharts
and Framer Motion covered data visualization and animation needs.
b) Back-end: FastAPI
FastAPI [22] was chosen for its native Python compatibility with the ML stack, automatic
Swagger documentation, and Pydantic-based request validation. Its asynchronous support was
essential for implementing live result streaming.
c) Database layer
The platform's data divides naturally into two categories that are relational records and a bio-
logical knowledge graph, whose storage and query requirements are fundamentally incompatible
within a single database system:
 PostgreSQL [23]: handles relational system data like user accounts, sessions, analysis his-
tory, and report metadata, where a xed schema, ACID compliance, CHECK constraints,
and native JSONB support are essential for maintaining data integrity across transactional
operations.
 Neo4j [24]: models the biological knowledge graph, where miRNAs regulate genes, genes
participate in pathways, and pathways interlink. Storing this structure relationally would
require deep, costly join chains; Neo4j expresses the same traversal as a single Cypher state-

2.7
Solution architecture
To guarantee a solid, scalable and well-structured design, the platform's architecture separates
system responsibilities across two complementary views:
 The logical architecture, which describes the main functional layers of the system.
 The software architecture, which species the technical organisation following a layered
Controller  Service  Repository pattern within a decoupled clientserver design [25].
2.7.1
Logical architecture
The logical architecture represents the functional structure of the system, independently of the
underlying technologies. The system can be decomposed into ve main layers:
 User Interface (Frontend): React.js is the technology used to create this layer of the
system. It allows a user to interact with the platform.
 API Gateway: Single point of entry for clients, taking care of routing, validation, JWT
authorization, and rate limiting.
 Analysis & AI Processing: The scientic core of the platform, including the ML models,
NLP entity extraction, and LLM-assisted report generation via the Groq API.
 Data Access: Allows accessing both persistence layers through a unied interface.
 Persistence: Two complementary stores, PostgreSQL for structured records and Neo4j
for the biological interaction network.

2.7.2
Software architecture
The platform adopts a decoupled clientserver model in which a React SPA communicates
with a FastAPI backend exclusively over a REST API. The backend follows a layered ar-
chitecture [25] organised around the Controller  Service  Repository pattern, enforcing
a strict separation of responsibilities [26]:
 Presentation tier (View): React.js SPA; all server communication is delegated to a thin
client-side service layer and no business logic resides in the browser.
 Controller layer: FastAPI routers; validate requests against Pydantic schemas, enforce
JWT authentication, and delegate processing to the appropriate service.
 Service layer: Encapsulates all domain and business logic, orchestrates ML, NLP and
report-generation pipelines, and delegates LLM text production to the Groq API [26].
 Repository layer: Abstracts access to both stores, SQLAlchemy for PostgreSQL and
Cypher for Neo4j, so business logic remains storage-agnostic [27].

4.3.6
Neo4j matching and duplicate avoidance
A critical feature of the NLP pipeline is preventing duplicate entities in the Neo4j database.
This section details the matching algorithms used to link extracted entities to existing nodes.
4.3.6.1
Neo4j matchers
The MIR-ACLE database uses Neo4j graph database. To prevent duplicate entities, four custom
matchers query existing nodes before insertion:
MirnaMatcher - Multi-step miRNA matching:
1. Exact match: Search by exact name (e.g., "hsa-miR-21-5p")
2. Normalized match: Clean and normalize name variations
3. Partial match: "miR-145" →nds "hsa-miR-145-5p"
4. Family match: Search by family (e.g., "miR-21") as last resort
GeneMatcher - Multi-criteria gene matching:
1. Primary: Search by Entrez ID (unique identier)
2. Secondary: Search by gene symbol (e.g., "TNF")
3. Tertiary: Search by gene name (e.g., "Tumor Necrosis Factor")
If a match is found at any level, the existing node is linked instead of creating a duplicate.
DiseaseMatcher - Leishmaniasis-focused matching:
1. Search by MeSH ID (e.g., "D007896" for leishmaniasis)
2. Search by disease name with normalization (case-insensitive, synonym handling)
3. Filter: Only diseases related to leishmaniasis are kept

Conclusion & Perspectives
Throughout this project at MIR-ACLE Biotech, we aspired to design and develop a platform
that accommodates and accelerates the research process through clear data browsing, a guided
workow, and AI-driven predictive analysis. Within the given time period, we were able to
implement the main features, from easily nding the right data to work on, to generating a full
report with all the needed sections, with an initial focus on leishmaniasis.
Choosing the right methodology proved essential; Scrum helped us move through the steps of
our project with both speed and precision. With stable and consistent progress, we went from
deep research on miRNAgene interactions, researchers' needs, and existing solutions, to build-
ing and integrating large datasets, making their visualization interactive and customizable, and
leveraging AI to accelerate key tasks such as analysis and report writing , altogether covering
the features needed for our platform to become an eective tool in easing what is otherwise a
heavy and slow research process.
While the project achieves its core objectives, we are aware that a platform of this nature is
never truly nished. Certain advanced features remain open for future development: enhanc-
ing NLP extraction accuracy, enabling extraction from gures, generating more personalized
and tailored reports, implementing a scoring system to assess data reliability, expanding the
database to cover additional diseases, and further strengthening the security layer. Each of these
improvements targets a specic limitation we identied during development, and together they
form a clear and realistic roadmap that will make the platform more robust, more precise, and
more competitive.
To summarize, MIR-ACLE will continuously keep evolving, but having a polished and func-
tional core already establishes it as a solid solution , one that genuinely satises the need
for a better working experience with miRNAgene-centered data. This positions it as a strong
competitor among existing platforms and lays the groundwork for steady, condent future steps.
Finally, this project was made possible through the close collaboration between two dierent
elds , computer science and biology, working together toward a shared goal. Completed under
the continuous supervision of our professional supervisor, with each step carefully evaluated and
tested, the platform stands as a trustworthy tool built with both technical care and scientic
relevance. We believe it will open real opportunities for researchers in a eld that urgently
needs intelligent, reliable, and integrated solutions.
