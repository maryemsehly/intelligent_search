General Introduction 
 
              The project is an e-commerce platform designed to offer an optimized online store 
catering to sellers and buyers. In a world where online commerce is experiencing 
exponential growth it is essential to provide an effective solution that meets the needs of 
merchants and consumers. 
              This platform will allow sellers to manage their products and orders while 
benefiting from a smart interface and advanced tools to optimize their sales. As for Buyers, 
they will have access to a big range of products organized with detailed descriptions and 
images, ensuring a smooth shopping experience. 
               This graduation project is part of the development of a modern interface, 
enhanced security to protect user data and to add new features based on market needs. With 
centralized and automated management, the platform aims to simplify the buying and 
selling process while ensuring increased transparency and reliability. 
             By integrating the latest web technologies and adopting a user experience-focused 
approach, the platform aims to become a reference in the world of online commerce. 
             This project helps solve many problems by facilitating merchants' access to a 
broader market and providing customers with a practical and secure platform for their 
purchases. The project will be presented in six chapters: 
Chapter I: Provides the overall context of the project, the chosen methodology, gives an 
overview of the hosting organization, and examines existing solutions.  
Chapter II: In this chapter we will talk about Requirements Analysis and Specifications 
Chapter III: presents the study and implementation of the first sprint, which covers user 
management including authentication and general account administration.

V. 
Choice of work methodology 
1. Differences between traditional methodologies and agile methodologies 
a. Classical methodologies 
Classical methodologies are an organized and sequential to software development, where the 
project is planned in detail from the beginning, and each phase is executed one after the other 
according to the set schedule .However, this approach may face difficulties in dealing with 
unexpected events or sudden changes, which can cause delays and increased costs. 
b. Agile methodologies 
 Agile methodologies rely on a more flexible and iterative approach, focusing on continuous 
collaboration between the development team, client, and stakeholders. These methodologies 
are designed to be adaptable to the ongoing changes in client requirements throughout the 
project development. They also encourage repeated work cycles and continuous testing to 
consistently improve the quality of the product. 
2. The agile framework adopted SCRUM 
To ensure the success of my project, I chose the SCRUM methodology because it allows for 
frequent and continuous adjustment throughout the work cycles, helping to meet the client’s 
needs. SCRUM enhances clear and effective communication between me and management 
through a set of key activities such as sprint planning, daily stand-up meetings, and sprint 
reviews.

a. Definition of SCRUM 
Scrum is a flexible framework used for software development following the Agile approach. It 
relies on iteration and collaboration to achieve common goals. The project is divided into short 
time periods called sprints, which usually last between two and four weeks. 
b. The fundamental principles of Scrum include 
Transparency: All information related to the project’s progress must be available to all team 
members to ensure a shared understanding and effective collaboration. 
Inspection: The team regularly reviews and monitors work results to ensure they meet customer 
needs and align with defined objective. 
Adaptation: Based on review results, improvements or changes are made to the workflow to 
ensure higher quality and better responsiveness to changing requirements.

c. Scrum roles 
Scrum master: He is the person who helps the team work in an organized way and makes sure 
everyone works in a comfortable and correct environment. 
Product owner: He is responsible for setting the goals of the project and what the customers 
need, and he follows the progress of the work. 
Scrum team: They are the people who do the technical tasks of developing and building the 
project. 
d. Scrum artifacts 
Product backlog: It is an organized list the contains all the features, improvements, and bug 
fixes that need to be added. The product owner prioritizes and regularly. Updates this list. 
Sprint backlog: It is a set of items selected from the product backlog that will be completed 
during the current sprint, along with the specific tasks that the development team will carry out. 
Increment: It is the final and prepared product at the sprint. This increment must include all 
the features that ware completed and tested during the sprint, and it must be deliverable or 
usable to gather feedback. 
e. Scrum events 
SCRUM incorporates a number of crucial activities that aid in organizing the software 
development process: 
Sprint planning: a meeting in which the development team establishes the objectives for the 
next sprint and arranges the work required to reach these objectives. 
Daily scrum: a 15-minute daily meeting where team members talk about their work and 
possible roadblocks.

2. Hardware architecture 
Our e-commerce platform uses a three-tier architecture, which is a software architecture that 
organizes the system into three layers: 
Presentation Layer: This is the interface that the user uses when using the platform. 
Business/Processing Layer: This layer carries out all of the business functions, such as order 
processing, inventory management, price and quantity calculation, and promotion calculations. 
Data Layer: This layer retains the product data, user data, order data, and invoice data in a 
structured and secure manner. 
Each layer has its own responsibilities, and the layers communicate in a structured and 
predictable manner to work together for a reliable platform. 
In this architecture we also identify: 
User:  The platform’s users are known as the vendor and client. The vendor controls and 
display their products and takes orders, while the client persuses items, adds them to their 
shopping cart, and completes the transaction.

3. MVC architecture 
Model-View-Controller, or MVC, is a popular programme design pattern in platform 
development. The programme is separated into three interrelated parts by this pattern: the 
Controller, the View, and the Model. 
The View is in charge of the user interface and information presentation, the Controller is in 
charge of accepting user instructions and facilitating communication between the Model and 
the View, and the Model represents the data and business logic of the programme.

Advanced features  
With the implementation of JWT for authentication, we were able to improve the security of 
our application to use tokens that are created when a user logs in. Then, when the user makes a 
request, we can use that token to authenticate the same user to gain secure access to our 
resources while protecting sensitive information. 
The way we use JWT follows these steps: 


===== PAGE 60 =====

E-commerce platform with AI virtual assistant  
2025-2026 
 
P a g e 60 | 131 
 
When a user logs into our application, they provide their credentials. 
The sever validated their credentials and created a JWT from that validated logged-in user’s 
information. 
The JWT is stored in a secure cookie in the user’s browser. This allows us to safely store the 
user’s token and to send that token automatically each time the user makes a request on the 
server. 
When the user logged, in their data was stored, so we are able to retrieve their data and change 
that data each time they make a request on the server while logged in. When the user makes 
changes to their profile or their data, the server will simply assign the new data to the same 
storage location. 
Each time the user makes a request, the JWT will be sent automatically in each request, allowing 
us to verify that a user is logged into their account without that user having to log in every time 
and enter their credentials. 
When the user has reached a point where they want to log out, the server will invalidate the 
JWT for that user by deleting the token stored in the cookie.

The route for product addition is for an authenticated seller to create a new product in the 
system. The process starts after the client sends a POST request with the product data to the 
server. 
The server will authenticate the seller to begin with. If the seller isn’t authenticated, a 401 
Unauthorized response will be returned. Next, the server will check if the required fields are 
present (name, description, price, category, sub-category, and sizes). If any fields are missing, 
a 400 bad request will be returned. 
The price must be validated to be a positive number. Sizes are parsed from a JSON string and 
must be validated to be an array that is not empty.  
The server will get the image from the request and upload each image in the client request to 
Cloudinary, obtaining the secure URLs, cleaning up temporary files after the uploads. A 400 
bad request response will be provided if no images are included. 
The server prepares the product data for persistence state by converting the data types, but also 
includes the creation date and seller ID. 
The product is persisted in the database. If it is successful, a 201 Created response is returned. 
In the event of an error while in this process, a 500 internal server error will be returned with 
the appropriate error message.

VII. 
Advanced features 
An additional feature that gives the vendor complete flexibility over tracking their 
own orders is the List Vendor Orders with Item Filtering capability. To make sure 
that all activities are carried out within their permitted scope, the system first uses 
JWT to confirm the vendor's identity when the function is called. Next, it uses the 
condition items to fetch from the database any orders that contain any vendor-related 
goods. The most recent orders are shown first by ordering the orders by creation date 
using vendor = vendorId. The function ensures data privacy and clarity by filtering 
the goods for each order so that only the vendor's products are left, excluding any 
things from other suppliers. 
The status of every item from the vendor is also used to automatically determine the overall 
order status: if all items are completed, the status is "completed"; if some items are in

platform, the filtered orders are ultimately returned to the vendor along with all pertinent 
information, including customer details, order date, total amount, overall order status, and the 
list of vendor-specific items. This is done while guaranteeing data accuracy and complete 
control over permissions.

Chapter VI 
Sprint 4: AI Integration 
 
I. 
Introduction 
This chapter intends to show the development of an intelligent chatbot incorporated into the e-
sales management platform. Project context: The role of Chatbots in enhancing the user 
experience in e-commerce is to improve the experience of requesting help in real-time (and 
interacting with customers). Objective: In order for customers to facilitate their interactions 
with the platform for product searching. Problem: How do we make a chatbot that is a virtual 
assistant that can understand customer inquiries, and provide responses accurately and quickly? 
II. 
Conceptual Study: 
1. Role of the Chatbot on the platform 
Chatbot role in the platform: The Chatbot finds products by name, category, and price and 
interacts with the user to answer questions about the product. 
2. Comparison with traditional chatbots 
Rule-based Chatbots: These chatbots operate within a framework of a number of fixed or 
predetermined rules (scripts). Their responses are limited to what has been coded previously. 
They cannot learn about new queries, and cannot adapt to new rules.  
Simple NLP Chatbots with Predefined Intents: These chatbots invoke a simple method in 
Natural Language Processing (NLP) to understand user intents, but they have limitations. In 
other words, they offer limited understanding and interactive capabilities. They only know 
predefined intentions with predefined scenarios.  


===== PAGE 115 =====

E-commerce platform with AI virtual assistant  
2025-2026 
 
P a g e 115 | 131 
 
LLM-based Chatbots (e.g., Ollama): LLM-based chatbots use large language models (LLMs) 
to help them understand natural language in totality. They can be flexible; they can provide 
some level of context awareness; they can adapt to new queries; they can customize display of 
detail; they can improve with time, and therefore they are more intellectually and scalable. 
3. Selecting technology 
I have selected the LLM Ollama model version llama3.1:8b to provide advanced natural 
language processing and answer the user's questions. The model is called through REST API 
which enables me to send questions to the model and have it send me a response directly. Users 
will experience a fast response time and switching from an LLM API takes little flexibility.  For 
the front end, I used either React or Vue.js to create a framework that provides an easily 
navigable and interactive user experience.

site. 
There will be a chat window embedded in the interface.

Build prompts, take action with the ollama model, handle dialogue logic, and manage context 
in dialogue as code. 
Integration/API Layer: REST API will coordinate communication between the OCR backend,

V. 
Implementation 
1. Data preprocessing 
During this project, three major steps were applied. The first was data cleaning, which means 
validating our inputs (i.e., checking that the message was a valid text), then removing empty 
words or words that had no relevance. The second was the data organization by organizing 
products from the previous steps displaying a list with clear information (the name, category, 
the description, sizes, cost, and ratings) to make the listings easier to search. The last was 
semantic indexing that was utilized through several ways: collecting valid size information, and 
filtering products related to size, fetching relevant products related to the size again through the 
mongoDB Text Index feature via the engine, and in cases when the voice assistant produces no 
relevant results, then you can simply fall back on the Regex to search or display the recency of 
the last products. By this process, retrieval is more flexible, and accurate, allowing the chatbot 
to provide relevant responses. 
2. LLM model and learning 
A pre-trained LLM of type LLaMA 3.1:8B was utilized without any further fine-tuning through 
the Ollama interface. The answer system relies on the model providing a response to the user 
question while retrieving context information from the database. The model does not use 
custom data, and answer quality was improved through a better design of prompts and injecting 
the retrieved product data into the context.

3. Integration with the platform 
The chatbot has been fully integrated with the e-commerce platform, which means the 
interaction will be seamless from a user experience perspective. Below is a summary of the 
integration: Frontend: The front-end implementation involves an embedded chat window 
designed in React (or Vue.js). The user is able to type a question or view the answer directly,

a user requests, and receives messages through a REST API. Builds a prompt for each question 
incorporating products retrieved from the database for context in the conversation. Delivers the 
prompt to the LLM model (Ollama llama3.1:8b), and retrieves intelligent response(s). Database 
(MongoDB): The database holds information about the product, user(s), and conversation 
history. The database contains text indexing to facilitate semantic search. REST API 
communication: allows connectivity between the front and back-end whilst allowing the server 
to programmatically deliver requests to the language model and get responses back effectively. 
This architecture allows the Chatbot integrated with the platform to successfully provide 
accurate answers linked to product available. And, do so with a seamless user experience.
