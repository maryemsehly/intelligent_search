RESUME 
Ce rapport présente notre projet de fin d’études qui consiste à réaliser site web dynamique de gestion 
des événements, des documents et de départements pour l’institut supérieur des études technologiques-l’ISET- 
de Gafsa. Le rapport expose les différentes phases de réalisation du logiciel proposé allant de l’analyse du 
problème en passant par la conception et la réalisation du système jusqu’aux tests de validation. 
L’application proposée offre un point d’accès où l’enseignant, l’étudiant et l’ensemble des personnels 
de l’institut, peuvent trouver les informations, outils et services numériques en rapport avec leurs activités 
pédagogiques et administratives. 
Les logiciels utilisés sont : WAMP Server, Notepad++. 
Mots clé : plateforme, PFE, gestion événement, étudiant, enseignant, département, documents, 
agent administrative, PHP, administrateur, HTML, CSS, Bootstrap. 
 
ABSTRACT 
 
This report presents our final graduation project of developing a dynamic event, document and 
department management website for the Higher Institute of Technological Studies-HITS- in Gafsa. The 
report outlines the different phases of the proposed application, ranging from problem analysis through the 
modeling and construction of the application to validation tests. 
The proposed application offers an access point where the professor, the student and all the staff of 
the institute, can find information, tools and digital services related to their educational and administrative 
activities. 
The software used are: WAMP Server, Notepad ++. 
Keywords: platform, FGP, event management, student, professor, department, documents, 
administrative agent, PHP, administrator, HTML, CSS, Bootstrap.

We have chosen Agile as the development methodology in order to optimize the

planning, collaboration, and improvement.

The agile software development emphasizes on four main values. 
 Individual and team interactions over processes and tools 
 Working software over comprehensive documentation 
 Customer collaboration over contract negotiation 
 Responding to change over following a plan 
The customer has early and frequent opportunities to look at the product and make 
decision and changes to the project. This is help us to improve the quality of our final project 
and to ensure the satisfaction of our final client.  
The agile methodology presents an iterative and incremental standard and which is 
based on the universal pictogram-based graphic modeling language UML (Unified Modeling 
Language). We adopted this language to design our project. With its various diagrams, UML 
provides a nifty way to represent various projections of the same representation by covering 
both the static and dynamic aspects of a system which allow its "physical" and "functional" 
aspect to be presented, respectively. [2] 
For this, it defines fourteen diagrams from UML 2.3 subdivided according to the views: 
 Static view: presented using structure diagrams such as object, class, packaging, 
component, deployment and finally architecture diagrams. 
 Behavioral view: Behavior diagrams bring together the use case diagram, the 
state transition diagram and the activity diagram. 
 Dynamic view: presented by means of interaction diagrams such as the 
sequence diagram, and collaboration. 
To avoid some technical details and report overload, in what follows we will only 
present a few diagrams that we have found useful for modeling our project, namely: The use 
case diagram, the sequence diagram, the class diagram. 
The agile method provides flexibility and offers the possibility of mixing several 
methods together throughout the project life cycle in order to choose and use the most 
appropriate principles for the project, work team and company. In such an approach, we break 
the "V" development cycle which begins with the receipt of the specifications with fixing of 
the architecture and ends with the delivery of the work to have collaborative work. .[3]

4.3. Architectural model 
In this part, we will present the architecture to be adapted within this project. We will

4.3.1. Three-tier architecture 
Using multi-layered application architecture, developers can create flexible and reusable 
applications. By segregating it into tiers, it became easier to add a specific layer or to modify 
existing one to an application than to redoing the entire work.  A three-tier architecture is 
typically composed of three tier: a presentation tier, a logic tier, and a data tier. 
On our case, we will need three tier: 
 Client: A user agent, commonly a web browser or web crawler, initiates 
communication by making a request for a specific resource using HTTP, and the server 
responds with the content of that resource or an error message. 
 Web server: a computer software and underlying hardware that accepts requests via 
HTTP, or HTTPS protocol. 
 Database management system (DBMS): the software that interacts with end users, 
applications, and the database itself to capture, manage, store and analyze the data.

4.3.2. MVC 
The Model-View-Controller is a design pattern intended to meet the needs of interactive 
applications. This architecture organizes the human-machine interface (HMI) by separating the 
issues related to the different components. It thus breaks down the different functionalities into 
three fundamental parts: [4] 
 Model (M): The model represents the internal behavior of the application. It gathers all that 
concerns the management and the integrity of the data by offering methods which ensures 
the treatment of the data  namely the insertion, the update, the recovery and the deletion of 
the data as well as the interaction with the base of data. 
 View (V): The view is the interface the user sees of the system and with which he interacts. 
These tasks can be summarized by receiving all actions and orders from the user, sending 
these events to the controller and representing the results returned by the model without 
performing any processing. 
 Controller (C): Event management, synchronization, and updating of the view and / or 
model and synchronizing them are the objectives of the controller. The latter receives all 
the events and actions of the user via the view and initiates the necessary and scheduled 
actions to be performed. Since it takes care of the synchronization of other parts, it requests 
modification of data from the model if necessary, and notifies the view to update itself.

3. Security process 
Security for our application is a major issue. We need to provide security through three 
mechanisms which are authentication, sessions and prevention of SQL injection vulnerabilities. 
Authentication generally refers to the process of confirming that a user is legitimate to 
access the system. In the case of an individual, authentication generally consists of verifying 
that he has proof of his identity or status, in the form of a password or an identifier. 
While the sessions allow us to save and transmit user information from page to another 
on our website. This information will be locked in "session variables". 
Typically, session variables will disappear when a user closes their browser. 
Finally, we are aware about the existence of SQL injections vulnerability, when user 
input is either incorrectly filtered for string literal escape characters embedded in SQL 
statements or user input is not strongly typed and unexpectedly executed. 


===== PAGE 92 =====

HITS of Gafsa  
Chapter 4: Implementation and tests validation 
FINAL GRADUATION PROJECT 
 
79 
To prevent this code injection technique, when a malicious SQL statements are 
inserted into an entry field for execution, we used a mysql_real_escape_string() function.
